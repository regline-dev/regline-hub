2. 라우팅·되물음 버그 수정 3건 완료

2-1. 인사 아닌 chitchat도 품목 후보로

설계(6-2/6-2a) 기준: 인사만 안내만 응답, 나머지는 전부 품목/수정 판별로. 실제론 classify_intent의 chitchat 결과 하나에 진짜 인사와 파싱 실패 텍스트가 섞여 있어서, "율무차 추가"(품목명+동사, 수량·단가 없음)가 안내만 문구로 떨어짐. 수정: llm_router_node에서 인사 여부(is_greeting)만으로 분기 — 인사면 안내만, 그 외는 전부 unclear 되물음(기존 경로 재사용). 특정 동사 키워드 나열 방식은 쓰지 않음(규칙 증식 방지). 첫 턴(has_lines=False)·미리보기 이후(has_lines=True) 양쪽 다 적용, 레거시 turn.py는 이 변경과 무관(별도 후처리 로직이라 미영향).

2-2. pending_kind 되물음 중 무관한 요청 인터럽트 처리

되물음 대기 중(pending_kind 설정됨)이면 _route_entry가 라우터를 건너뛰고 해당 tool로 직행 — 그래서 무관한 새 요청이 오면 tool이 답으로 해석 실패, 같은 질문만 반복(재현: conflict 되물음 중 "율무차 추가" → 무한 반복). 정책: 계산 가능한 결과값이 있으면(conflict/field_conflict) 그 값으로 확정 안내 후 새 메시지를 라우터로 전달, 없으면(fill_name/unclear/name_confirm/ask_item/add_confirm) 새 메시지 무시하고 같은 품목 질문 유지. add_confirm은 "동의 여부"라 계산값이 아니므로 후자로 분류.

2-3. field_conflict 인터럽트 기본값 — 보수적 선택

field_conflict는 같은 품목명이 확정 목록과 새 입력 양쪽에 있는데 수량/단가가 다를 때 발생(options[0]=기존 확정값, options[1]=신규 입력, 항상 2개). 인터럽트 시 처음엔 options[-1](신규값)을 기본값으로 썼는데, 신규 입력이 검증 전 값(오독 가능성 있음)이라 무응답 상황에 조용히 확정하기엔 위험 판단 → options[0](기존 확정값 유지)으로 변경.

3. 수량 파싱 · 결측 대칭 처리 진행중(방향 확정, 완료 보고 대기)

재현: "율무차" → "2 3000원"(단위 없는 2가 수량으로 인식 안 됨 → 단가만 3000원 반영, 수량 결측) → "2개 2000원"(완전한 답인데도 fill_name 재개 로직이 "단가 결측"만 채울 수 있어서 거부, "단가를 확인할 수 없어요"라는 잘못된 문구 반복). 확정 방향:

항목결정
단위 없는 앞숫자뒤에 단가(원)가 따라오면 수량으로 인식 ("2 3000원" → 수량 2)
fillable 판정check_completeness가 단가 결측뿐 아니라 수량 결측도 채울 대상으로 인식하도록 대칭 확장
되물음 문구수량 결측 전용 문구 신설("수량을 확인할 수 없어요. 몇 개인가요?") — 기존 단가 결측 문구를 재사용하지 않음
재개 시 값 반영완전한 답("2개 2000원")이 오면 결측 필드만 뽑지 않고, 답변에 포함된 값 전부(수량·단가)로 최신값 덮어쓰기 — 이전 턴의 스테일 값(3000원) 무시

5. 문서종류 자동선택 완료 (Cursor 보고)
